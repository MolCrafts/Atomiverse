# Diamond-Si k-point stress oracle

These are actual CP2K 2026.2 (`git:c92cc08`) outputs from 2026-10-25,
using `/opt/homebrew/bin/cp2k.psmp` and its installed MOLOPT/GTH data.
`reference.json` records input/output SHA256, commands, environment, full
stress tensors, convergence, wall times and the acceptance bounds declared
before the new comparisons. `singlegrid.cp2k.txt` and `multigrid.cp2k.txt`
are complete successful outputs; `cp2k-version.txt` is the binary's output.

The inputs are `../gpw-kpoint-stress.inp` and
`../gpw-kpoint-stress-multigrid.inp`: PBE / DZVP-MOLOPT-GTH / GTH-PBE-q4,
Si BCT four-atom cell at a=5.43 Angstrom, MP1x1x2, CUTOFF100 Ry,
NGRIDS1 or NGRIDS4/REL_CUTOFF40 Ry. `CORE_PPL GRID` matches the native
`local_pp_on_grid=true`. Both runs printed `SCF run converged in 12 steps`
at `EPS_SCF1e-10` and printed an **analytical** stress tensor. Native stress
uses a fixed-density Lagrangian strain difference; it is not a closed-form
analytical tensor. Native reconverged strain differences are an additional
internal consistency check, never the external oracle.

Reproduce in a fresh work directory, with either input copied there:

```sh
ln -s /opt/homebrew/share/cp2k/data/BASIS_MOLOPT BASIS_MOLOPT
ln -s /opt/homebrew/share/cp2k/data/GTH_POTENTIALS GTH_POTENTIALS
env -u OMP_PROC_BIND -u OMP_PLACES OMP_NUM_THREADS=8 OPENBLAS_NUM_THREADS=1 \
  /opt/homebrew/bin/cp2k.psmp -i gpw-kpoint-stress.inp -o cp2k.out
```

Use `gpw-kpoint-stress-multigrid.inp` for the second run. These are offline
commands; regressions never invoke CP2K. Both walls include the full
`ENERGY_FORCE` process and analytical stress (63.903604s / 17.833723s,
respectively). Native product stress is printed separately in both existing sections:
`gpw-kpoint-stress` checks the single-grid energy/tensor and its original
relaxed-FD supplement; `gpw-multigrid-kpoints` adds the 100 Ry multigrid
energy/full tensor alongside its existing 150 Ry energy and 40 Ry identity
gates. Both complete sections assert a 60s limit. No new parameter section
is introduced. Report the algorithmic difference
when comparing walls; the supplemental native verification work is separate
from the physical product calculation.

Raw stress is in bar. `reference.json` converts it independently to Ha/Bohr3
using `1e5 * a0**3 / Eh` with CODATA2018 SI constants. No scientific value
was generated by Atomiverse or a reimplementation. Earlier incomplete
numerical-stress / screening diagnostics remain in the task evidence under
`/tmp/atv-gpw-repair-evidence/kpoint-pressure-inputs/`; none is a pin.

The final registered native run (2026-10-25) passed both complete sections:
SG 42.176594s, MG 17.708007s, with product walls 20.617223s/13.235127s.
`native-validation.txt` preserves the exact comparison output. Native CTest
requests `OMP_NUM_THREADS=8` / `OPENBLAS_NUM_THREADS=8`; these CP2K
processes requested `OMP_NUM_THREADS=8` / `OPENBLAS_NUM_THREADS=1`.
Those values are environment requests. CP2K's internal BLAS thread width
was not queried and may be set internally; `OPENBLAS_NUM_THREADS=1` alone
does not prove single-thread BLAS for an OpenMP OpenBLAS build. The recorded
timings do not establish a fair matched-width wall ratio or speedup. Native values are validation
observations, not scientific reference pins.
