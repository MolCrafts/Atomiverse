# Reference: AM1-BCC / ABCG2 charges vs AmberTools antechamber

```text
oracle: ambertools
oracle_version: AmberTools 26.1 (antechamber; SQM version 19)
```

## Method

This case covers AM1-BCC, the GAFF charge model, and its GAFF2 refit ABCG2:

- AM1-BCC: Jakalian, Jack & Bayly, *J. Comput. Chem.* **23**, 1623–1641 (2002); table `BCCPARM.DAT`.
- ABCG2: table `BCCPARM_ABCG2.DAT`.
- Code: `cpu::semiempirical::AM1BCCCharges`.

The model has three stages:

1. AM1 Mulliken charges at the input geometry. ATV AM1 is closed-shell RHF.
2. Averaging over topologically equivalent atoms (antechamber `-eq 1`).
3. Bond charge increments, looked up by BCC atom type and bond type and perceived from connectivity (molrs `BccModel`).

## Oracle run

The script is `tools/bcc_oracle/run_antechamber.sh`. The inputs are generated by
`tools/bcc_oracle/make_inputs.py`, and the captured outputs are in
`tools/bcc_oracle/outputs/`. Each case runs:

```bash
antechamber -i <mol>.mol2 -fi mol2 -o <mol>_<m>.ac -fo ac -c <m> -nc <q> -pf y \
            -ek "qm_theory='AM1', maxcyc=0, scfconv=1.d-10"
```

`maxcyc=0` makes it one SCF at the input geometry, with no optimisation.
Coordinates are pre-rounded to the 1e-3 Å that antechamber writes into
`sqm.in`, so ATV and sqm see the same geometry.

The case also checks that the two parameter sets are told apart. AM1-BCC and
ABCG2 differ by up to 0.21 e on the acetate carboxylate carbon, which is more
than 300 tolerances.

## Tolerance rationale

**The precision floor is the oracle's print format.** sqm prints Mulliken
charges to 3 decimals, and antechamber reads that rounded table into the BCC
stage. Every oracle charge therefore carries up to ±5e-4 e of rounding from its
AM1 input.

- Every measured base residual (max 4.18e-4) is below that half-ULP. That
  means ATV AM1 and sqm AM1 agree to the precision sqm prints.
- The final residuals are the equivalence-averaged base residuals and nothing
  more. For example, the acetate methyl H residual is −2.83e-4 =
  mean(−1.4e-5, −4.18e-4, −4.18e-4). So the BCC typing and the increment rows
  agree exactly.

The 6e-4 tolerance is that 5e-4 half-ULP plus 1e-4 of headroom. The headroom
covers the CODATA-vs-frozen-1980s physical-constant floor, which
`am1-water-mopac-energy` measured for NDDO against MOPAC.

A wrong BCC row or a mistyped atom shifts charges by at least ~1e-2 e, roughly
20 tolerances. Skipping equivalencing on phenol would leave C2/C6 split by
6.5e-2 e, which the equivalence-class check fails outright.

**No tolerance was widened to make a check pass.** The tolerances were set from
the oracle's print precision after the residuals were measured.

## Gaps

- **Base-charge precision.** sqm prints no more than 3 decimals of Mulliken
  charge, with or without `printcharges` or `verbosity`. A tighter AM1 pin
  needs another oracle; the NDDO family's oracle is OpenMOPAC.
- **No geometry optimisation.** antechamber's default optimises with sqm
  first. This case pins the fixed-geometry path. To optimise first, compose
  `Minimize` over a mounted `AM1`. That path is not covered here because the
  SE-only build has `ATV_BUILD_MINIMIZER=OFF`.
- **No fair wall-time comparison.** sqm is fast for molecules this small, and
  ATV runs the whole case (4 SCF) in about 0.5 s wall on 48 threads.
